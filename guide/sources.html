History remediation is not complete, and a session branch cannot complete it. No later commit, no Pages exclusion and no passing scan removes an earlier Git object. This clone is shallow (its .git carries a shallow marker, so only part of the history was fetched), and a partial clone measures only what it holds. The instrument now lives in the repository: python3 scripts/privacy-history-audit.py inventories every reachable object under the same rules as the working-tree gate and prints counts and paths only, never a matched string; run it from a git clone --mirror of the repository for an answer that means something. The written runbook, with the consequence of each option, is docs/history-remediation-runbook.md in this repository, which is not published on this site. GitHub’s own procedure is the authority: sensitive-data removal ↗ — rewrite with git-filter-repo 2.47 or newer, read the affected refs/pull/*/head entries, force-push, then ask GitHub Support to remove cached views and pull-request references, because refs/pull/* is read-only and cannot be pushed. Rewriting also discards work other sessions built on the old history, so it is an owner decision made with a freeze, not a cleanup step in a task list. Clones and forks held by other people are outside every one of those steps.
Read the trade-off before changing visibility. GitHub states that on GitHub Free for personal accounts and organizations, any published GitHub Pages site is automatically unpublished when a repository becomes private; that a custom domain’s DNS records should be removed or updated before the change, to avoid a domain-takeover risk; and that public forks are detached into a new network and are not made private — GitHub Docs on setting repository visibility ↗. This guide is generated from the repository by one build command, so republishing it elsewhere is a rebuild rather than a reconstruction, which is what makes the private-repository option cheaper for a household than it looks. Making the repository private, or removing the retained analysis tree from the default branch, are the two owner decisions on the Suggestions page (S16 and S25); neither is performed by any session.
Important: A passing privacy scan cannot prove anonymity or clean previously published history. GitHub warns that commits may remain reachable through pull requests, caches, forks and clones. Do not put personal information, private links or financial documents in this repository.
